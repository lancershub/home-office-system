# P0/P1 修复与部署说明

## 修复对应关系

| 原问题 | 实现 |
| --- | --- |
| 管理接口未鉴权 | Spring Security 统一过滤链；管理员/员工路由分离；未列出的路由默认拒绝；401/403；HTTP Session 固定攻击防护 |
| WebSocket 冒充用户 | Spring WebSocket 复用认证 Principal；握手路径身份必须匹配；同源策略且拒绝无 Origin；每次消息及推送验证原 HTTP 会话；退出/会话销毁关闭连接 |
| 明文及固定密码 | BCrypt cost 12；管理员凭据入库；注册和后台新增均校验密码；旧明文拒绝登录；独立密码重置工具；登录/注册按 IP 限速 |
| JSP/聊天/文件名 XSS | 用户文本通过 c:out 或 DOM text/textContent 输出；动态事件使用绑定函数；修复注册成功页面反射输出；聊天历史和即时消息同样按文本处理 |
| GET 写入与 CSRF | 所有业务写接口明确 POST；登录、退出、注册和业务写入启用 CSRF；表单隐藏字段、AJAX 请求头；上传通过 multipart AJAX 请求头携带 token |
| 重复打卡/覆盖下班时间 | 用户+工作日唯一键；重复上班不改初始时间；下班使用状态条件更新；未上班先下班返回400；启动时验证数据库约束 |
| 消息保存和推送不一致 | 服务由 Spring 注入；持久化成功才推送/ACK；Jackson 序列化；clientId 唯一键去重并校验重试内容一致；失败消息可手工重试；历史按 ID 游标每页100条 |
| 文件与数据库不一致 | UPLOADING→ACTIVE→PENDING_DELETE；先记录上传意图，再写临时文件及移动；删除先留墓碑，再删磁盘，最后删元数据；清理任务重试；超时上传可回收 |
| 构建不可复现 | 删除预览参数；WAR packaging；Spring/Security/Jackson BOM；删除重复依赖和 Fastjson；标准 Maven Wrapper + 发行包 SHA256 校验 |
| 附加修复 | 数据库凭据外置；CSV字段转义与公式防护；考勤分页及分批导出；不再把“均已打卡”称作“全勤”；前端库本地化并保留许可 |

文件上传单文件上限20MiB、个人配额1GiB（包含回收站和待清理记录）。上传意图创建与配额判断通过用户行锁串行化。
上传不开放可执行网页扩展名，文件统一使用随机存储键及 attachment 下载，不作为静态网页提供。
文件类型白名单不等同于恶意文件扫描；项目不解压、执行或内联预览上传文件。

## 已有数据库升级顺序

1. 停止旧应用写入，备份数据库及原文件目录。
2. 用 DDL 账号运行 `src/main/resources/db/migrations/V1__security_and_consistency.sql`。
   - 重复考勤记录、空 user_id/work_date、重复文件键会中止迁移，不会自动删历史数据。
   - 根据实际业务确认应保留/合并的考勤记录，再重试。
   - 如果过程调用失败，先检查错误并执行 `DROP PROCEDURE office_security_v1;` 后重跑脚本。
   - MySQL DDL 可能独立提交，回滚应使用备份；不要假定外层事务可撤销全部迁移。
   - 脚本针对现有代码所用的 MySQL 表结构；如果本地做过表结构修改，先在数据库副本验证。
3. 设置环境变量，尤其是 `OFFICE_UPLOAD_DIR` 指向**原来的文件目录**（旧版是运行用户 home 下的 file-cabinet），或先将原文件完整复制到新目录。
4. 初始化管理员新密码；旧员工明文密码全部需要重置。工具参数换成员工数字ID即可：
   `java -cp "target/classes;target/home-office/WEB-INF/lib/*" com.yourcompany.reception.util.AccountPasswordTool 1`
   工具不输出密码或哈希，不支持把密码写入命令行参数。请通过可信渠道交付新密码。
5. 如果原 jdbc.properties 使用过真实凭据，轮换该数据库密码。当前工作树已不包含密码，但此变更不会改写 Git 历史或服务器上的凭据。
6. 部署新 WAR 并重新启动应用。会话持久化已关闭，旧登录态不会跨重启恢复。
7. 验证普通员工不能访问管理接口、两次打卡不生成两条记录、文件原数据可下载、聊天退出立即断开。

**此次修复没有在原业务数据库执行迁移，也没有修改原数据库账号密码。**

## 行为边界

- 保留 Java 8 / SSM / JSP 架构，未迁移到 Spring Boot/Jakarta。
- 部门、机构和其他既有功能保留原接口返回格式，避免破坏页面；权限拒绝使用 HTTP 401/403。
- 聊天 ACK 表示“数据库已保存”，不代表接收人已读或已收到。断线后重新加载当前会话最近100条，更早记录按游标加载。
- 未确认消息保存在当前页面内存，刷新/关闭页面不保留重试队列；确认丢失时可先查询历史。多实例路由、离线推送及已读回执不在本次实现范围。
- 登录限速与在线连接表为单实例内存状态；扩容时需共享限流和消息路由。
- 文件清理每分钟运行，超过1小时未完成的上传进入清理状态。存储长期不可用时墓碑会保留，需要监控任务日志。
- 新库脚本带外键；旧库迁移不会擅自改变全部业务外键关系。
- 导出分批读取且固定初始最大ID，不承诺并发修改场景下的数据库快照。
- 仍需在实际部署环境验证 HTTPS、代理配置、数据库备份及还原流程。

## 可重复验证

默认执行 `mvnw.cmd verify` 使用 H2（MySQL兼容模式）进行隔离测试，不需要业务数据库配置。

真实 MySQL 测试需要专门的本地测试实例，监听127.0.0.1:13307，root测试账号使用空密码，仅限隔离实例。设置：

```powershell
$env:OFFICE_TEST_MYSQL_URL = 'jdbc:mysql://127.0.0.1:13307/'
.\mvnw.cmd verify
Remove-Item Env:OFFICE_TEST_MYSQL_URL
```

测试只接受该地址，每个持久化测试新建随机 `office_security_test_<UUID>` 数据库并在结束后删除，不接受原业务库地址。

浏览器回归脚本 `scripts/browser-smoke.cjs` 只接受 `http://127.0.0.1:18089/office`：
先为隔离 Tomcat 配置空测试库并执行新库脚本、初始化测试管理员，再设置 `OFFICE_SMOKE_ADMIN_PASSWORD`。
使用 Node.js 及 `playwright-core`、`ws`，将对应 node_modules 放入 NODE_PATH；本机 Chrome 路径可通过 CHROME_PATH 指定。
脚本创建测试员工、组织、考勤、日程、文件和聊天数据，不会自动清空此浏览器测试数据库。
每次测试至少覆盖11个JSP页面、脚本注入字符串、编辑表单、真实浏览器上传、角色检查、并发打卡、文件归属及删除恢复、WebSocket身份/Origin/ACK/去重/退出。

浏览器发行依赖已锁定并存放在 `src/main/webapp/lib`。仅维护者更新库时才需要临时 npm 安装并运行 `scripts/vendor-assets.cjs`。
